MRD Data Layer — End-to-End Flow

From raw source (Snowflake or CSV) all the way to a user query answered with insights + optional deck. Self-contained reference for the feature/data-layer branch.

0

One-time setup

automated · ~10 min

Install the package, drop credentials into .env, and (if you have a new connector instance) declare it in connectors/<name>.yaml. csv_local + snowflake_dz already exist.

commands

py -3 -m pip install -e .
cp .env.example .env   # fill creds

artifacts

.env (gitignored), connectors/snowflake_dz.yaml, connectors/csv_local.yaml

1

Pick source for a table

user picks · automated dispatch

Engine dispatches by connector type. Same downstream pipeline regardless of source.

CSV path
Drop file in /data/
mrd onboard csv_local <file.csv>
or
Snowflake path
Table in any DB.SCHEMA you can SELECT from
mrd onboard snowflake_dz <DB.SCHEMA.TABLE>
2

Fetch → local parquet cache

automated

Connector pulls the source into data/_cache/<table>.parquet with a row-cap guardrail (default 10M). For Snowflake: cursor fetch via SSO. For CSV: read + re-save as parquet. Returns a Manifest (connector, fetched_at, row_count, column_hash, cache_path).

files written

data/_cache/<table>.parquet

guardrails

row_cap 10M · SSO timeout · column-hash for drift

3

Profile every column

automated

Statistical profiler: per column dtype, null %, distinct count, top-K values, min/max, sample rows, role guess (key / dimension / metric / date / flag). This grounds the LLM step so it can't hallucinate.

writes profiles/<table>.json

4

Propose metadata (LLM)

automated · Claude CLI

Claude Code CLI (headless claude -p, prompt piped via stdin) reads the profile JSON + column samples and proposes: table description, grain, business meaning per column, synonyms, role, known issues (rollup rows, biosimilar traps, coding-system caveats like NDC zero-padding). Falls back to a heuristic backend if the CLI is unavailable.

backends

claude_cli (default) · heuristic (fallback) · anthropic_api (stub)

writes

metadata/<table>.yaml.proposed

5

User gate: review metadata

user confirmation

Diff .yaml.proposed against existing (if any) and accept / edit / reject per top-level field. Optional per-column drill-down. Auto-accept mode for batch onboarding. Promotes .yaml.proposed → .yaml. 

mrd review <table>            # interactive
mrd review <table> --auto     # headless accept-all

writes metadata/<table>.yaml (the canonical dictionary)

↻

Repeat steps 1–5 for every table

per-table loop

Onboard each new source / file in turn. Order doesn't matter. Existing onboarded tables aren't affected. Once you've onboarded enough tables to join, proceed.

7

Discover candidate joins

automated

Engine scores every column pair across onboarded tables on three signals: name match (exact / strong substring), Jaccard value overlap on stringified distincts (sample-capped), and cardinality (1:1 / 1:N / N:1 / N:M). Optional one-line LLM rationale per candidate (via Claude CLI). Output is a ranked table with confidence + sample overlap. 

mrd joins recommend                  # ranked candidate list
mrd joins recommend --no-rationales  # skip LLM rationale (faster)

writes profiles/join_candidates.json

8

User gate: confirm joins

user confirmation

Two modes: pick specific candidates by index, or accept all above threshold. Confirmed edges are appended idempotently to metadata/relationships.yaml, carrying provenance (auto-discovered, name_match, jaccard, overlap, rationale). The hand-curated edges that already live in relationships.yaml are preserved. 

mrd joins accept 0 2 4 7      # cherry-pick
mrd joins recommend --accept-all   # bulk

writes metadata/relationships.yaml

9

Validate the data layer

validation gate

Extended schema gate. For each dictionary: cache exists, columns match, dtypes parse, column hash unchanged. Cross-checks relationships.yaml references against every column in every dictionary. With --include-remote, also handshakes Snowflake and diffs the live schema vs the dictionary. 

mrd validate                 # local checks
py -3 scripts/validate_schema.py --include-remote   # + Snowflake drift

exit 0 = clear · 1 = halt · 2 = warnings only

10

Data layer ready — foundation locked in

milestone

At this point every onboarded table has a dictionary, a profile, a manifest, and a loadable cache. Every confirmed join lives in relationships.yaml. The engine sees a uniform interface via mrd_engine.loader.load(<table>) regardless of source. mrd status shows the inventory.

11

User asks a query

query time

Plain English. The Claude Code orchestrator parses it per CLAUDE.md protocol: extract entities, metrics, time window, output grain.

example: "Top 10 brands by 2024 patient claim count, with their IQVIA latest weekly TRx"

12

Feasibility check + plan

query time · automated

Engine checks the query against dictionaries, relationships, and semantic rules. Three outcomes: feasible, feasible with assumptions (surfaced for user confirmation), or data / semantic gap (reported, stopped). If feasible, writes analysis_plan.md with tables, joins, filters, assumptions, expected row count.

writes output/run_<id>/analysis_plan.md + query.txt

13

Generate analysis_code.py

query time · pandas codegen

Standalone, re-runnable script. Reads tables via mrd_engine.loader.load(<table>) — never pd.read_csv directly. Copies joins verbatim from relationships.yaml. Applies standing filters. Slide-size convention: ≤2000 rows in result.csv. 

from mrd_engine.loader import load
claims = load("ADHOC_FINAL_TABLE")          # Snowflake parquet
cross  = load("ndc_brand_crosswalk")        # csv_local parquet
weekly = load("Weekly_Data_Tabular")        # legacy CSV
# ... joins, filters, aggs ...
result.to_csv("result.csv", index=False)
14

Execute (pandas) + write manifest

query time · automated

Pandas runs locally against parquet / CSV caches. No SQL push-down today — all compute is local pandas on the cached data. Output table written to result.csv. A source_manifest.json pins connector + fetched_at + column_hash per source touched. Reproducible.

writes output/run_<id>/result.csv + source_manifest.json

15

Validate the result

validation gate

scripts/validate_result.py: row count vs plan, slide-size cap, null audit on metric columns, duplicate-row check (catches join fan-out). Failure = engine does not deliver; plan or code gets fixed and re-run.

exit 0 PASS · 1 FAIL · 2 warnings

16

Insights → takeaways.md + context.md

query time · automated

2–4 numbered takeaways, every one traceable to a number in result.csv. Uses semantic/context.md rules to explain patterns. Flags caveats (provisional weeks, synthetic crosswalks, projected vs adjusted volumes).

writes takeaways.md + context.md — completes the 6-file contract

17

Deliver + ask about deck

user gate · default stop

Engine confirms delivery with the headline + run-folder path. Then asks "Do you want me to build a slide deck for this?" Default stop. Deck only built on explicit yes.

18

Optional: build deck (python-pptx)

opt-in · automated

On explicit user yes: write deck_spec.json, run scripts/build_deck_pptx.py output/<run_id>. Renders a DataZymes/Otsuka-style deck (navy section strip, statement title, italic dek, native line chart, numbered insight blocks, TL;DR bar). Integer-EMU sanitizer + round-trip validation. Numbers read live from result.csv — never hard-coded.

writes deck_spec.json + deck.pptx

Mental model in one line: connector → fetch → profile → propose → user confirms metadata → joins → user confirms joins → validate → uniform load() surface → query → plan → pandas codegen → result + manifest → validate → insights → optional deck.

Two user gates: metadata signoff (per table), joins signoff (across tables). Everything else is automated.

Engine touch points:

  • mrd_engine.loader.load(table) — single source-agnostic read surface.
  • mrd_engine.runs.manifest.write_manifest() — reproducibility per run.
  • scripts/validate_schema.py — pre-flight gate (boot-time).
  • scripts/validate_result.py — post-execution gate.

Not yet wired: SQL push-down to Snowflake (would require DuckDB federation; deferred). Anthropic API metadata backend (stubbed). Refresh-cadence TTL (manual re-onboard for now).
