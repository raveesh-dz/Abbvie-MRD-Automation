03/ 12A rule is born: RULE-010
Technical · proof

"Holdout" became a precise, reusable rule

The definition that produces the 43, saved and git-committed so the engine never re-learns it.

We co-defined Holdout as a five-way classification on a single ratio. It was auto-saved as RULE-010 and committed, meaning the next holdout question reuses it for free.

GroupConditionStatus
no_cd_nbrxSKY = 0 and STEL = 0Holdout
stelara_onlySTEL > 0 and SKY = 0Holdout
both_lean_stelaraboth > 0 and ratio ≥ 0.5Holdout
both_lean_skyriziboth > 0 and ratio < 0.5Non-Holdout
skyrizi_onlySTEL = 0 and SKY > 0Non-Holdout

ratio = STELARA / SKYRIZI. Boundary is ≥ 0.5 (not "> 0.5"). Committed: rule: RULE-010 SKYRIZI Holdout classification (63c87bd).

A definition isn't enough: the engine still refuses to act until the join to the holdout universe is declared.

res["skyrizi_cd_nbrx_13wk"] = res["skyrizi_cd_nbrx_13wk"].fillna(0.0)
def group(row):
    sk, st, ra = row["skyrizi..."], row["stelara..."], row["_ratio_num"]
    if sk == 0 and st == 0: return "no_cd_nbrx"
    if sk == 0 and st > 0: return "stelara_only"
    if st == 0 and sk > 0: return "skyrizi_only"
    return "both_lean_stelara" if ra >= RATIO_THRESHOLD else "both_lean_skyrizi"
